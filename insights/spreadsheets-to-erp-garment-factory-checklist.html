From spreadsheets to ERP: a migration checklist for garment factories

What to clean, what to move first and what to leave behind when a factory retires its Excel files.

TechBeez RMG solutions team 7 December 2023 7 min read

On this page

  2. 2. Clean the master data first
  3. 3. Go live in the order work flows
  4. 4. Run in parallel, but briefly
  5. 5. Train by role, not by screen
  6. Key takeaways

Most garment factories do not choose spreadsheets. They grow into them, one order sheet, costing file and TNA workbook at a time, until the business runs on hundreds of files that only a few people fully understand.

Moving to an ERP is less about software than about data and habits. This is the checklist we use with factories before the first module goes live.

1. Map the files you actually use

List every spreadsheet that a decision depends on: order sheets, costing files, booking sheets, TNA calendars, production trackers, commercial and shipment files. For each one, note who owns it, who reads it, and which other files copy data from it. The copies are where most errors come from.

2. Clean the master data first

An ERP is only as good as its master data. Before migration, agree one clean list of:

  • Buyers and their brands or departments.
  • Suppliers, with the items each one supplies.
  • Fabrics and trims, with consistent names, units and codes.
  • Colours, size ranges and product categories.

Expect duplicates: the same supplier spelled four ways, or the same trim under two codes. Merging them is tedious, but it is the single most valuable step in the whole project.

Do not migrate history you will not useBring over open orders and the masters. Closed orders from earlier seasons can stay in an archive folder for reference.

3. Go live in the order work flows

Start where an order starts. A common sequence is:

  1. Masters: buyers, suppliers, items, styles.
  2. Merchandising: orders, costing and approvals.
  3. Planning: TNA and material booking.
  4. Purchasing and store: supplier POs and receipts.
  5. Production tracking and order closing.

Each step feeds the next, so people see the benefit straight away instead of entering data that nothing uses yet.

4. Run in parallel, but briefly

Run the old files and the new system side by side for a short, fixed period, usually a few weeks per module, then switch the files to read-only. Long parallel runs double the work and quietly keep the spreadsheet as the real system.

5. Train by role, not by screen

Merchandisers, store keepers and accounts staff need different things. Short, role-based sessions using their own live orders work far better than a general tour of every menu.

Key takeaways

  • Map which files decisions depend on and where data is copied.
  • Clean and de-duplicate master data before anything else.
  • Go live in the order that work flows, starting with merchandising.
  • Keep the parallel run short, then make the old files read-only.
